FTP-1 本身无法提供 200 h 独立夹爪表面触觉，至少还缺 **115.763 h**。
此前检查的 UniVTAC 全部轨迹约 2.41 h，也不足以填补这个缺口；其 5.1
press_depth 操作部分约 0.885 h 可作为明确形变表示的小规模补充候选。

建议将 200 h 留作目标上限，先核实这 84.24 h 中真正可用的部分，再寻找新的
夹爪来源。不要为凑数加入 wrist wrench-only 数据，也不把重复采样称为新数据。
若后续接受以已验证的较小夹爪库开始训练，可以维持 25% 采样比例；需单独报告

夹爪族内部暂不固定虚假的精确权重：先以各来源的有效小时为基准，给 D-WHEEL
设置不超过夹爪窗口 50% 的初始上限，其余按有效小时分配；仅当标定与质量检查
通过后才进入 T 来源。Mini 小来源用于接通流程，不通过强烈重复采样掩盖容量缺口。

## 3. 当前只做样例的执行边界

1. 14 个非 Sharpa 来源各选 1–2 个任务、5–10 条完整 episode，覆盖正常接触、
   无接触、边界和缺失观测；力向量来源只验证 V/原始字段保留，不伪造空间图。
2. 为样例单独生成选中 census、split 与 publication，不把全库未完成的目录
   伪装成完整发布。已有完整桶可作为提取样例的输入，不再转一遍。
3. 先补 episode 级选择能力，避免为几条示例复制整块 50–280 GiB 的任务归档。
   首轮工作集按累计字节控制在 10 GiB 左右；达到上限即停止扩充样例。
4. 对样例依次检查：v3 回读、时间/区域/有效性、强度转换、真实 batch、四模态
   forward/backward、save/resume。完整规模多 GPU 测试另行安排。
5. 样例流程通过、来源分配确定后，才提交按所选 episode 清单处理的 CPU 作业。

真实 Mini 预览已验证能出现与接触形状相关的响应，但还发现首帧持物、通道
约定和卸载残留问题。预览不作为正式形变标签；详见
[实测报告](ftp1_gelsight_preview_20261028.md)。

## 4. BOS 与 PFS 分工

- BOS：原归档、新生成的已验证 v3、触觉 sidecar、不可变 manifest 的长期存储。
  新产物使用独立 TouchWAM 前缀，不能写回 Hugging Face 原始来源目录。
- PFS：保留已经在用的三批旧数据；新增部分只保留小样例、队列状态与本次选中
  分片的有预算缓存。现有三批不为更换格式再次复制。
- CPU 作业：读取选中范围，写本地/限额暂存，验证后上传 BOS，校验对象 hash，
  最后写完成 manifest。BOS 全部验证成功后才清理对应暂存。
- 训练：按不可变 manifest 提前取下一批分片至节点本地或小规模 PFS 缓存。
  现 reader 使用 POSIX 路径、视频 seek、npy mmap，尚不能直接读取 bos://；
  不把“BOS 已挂载”当作多卡随机读性能已经通过。

现有 stage queue 的任务数量限制不是磁盘字节上限，也不会自动淘汰已完成
原始段。按 episode 选择、字节预算、上传校验和缓存淘汰是后续存储改造项，
不能声称已经上线。
