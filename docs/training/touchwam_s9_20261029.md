# TouchWAM six-source S9 acceleration

The current launcher default has subsequently advanced to the validated batch-8,
no-recompute recipe. See `touchwam_bs8_norecompute_20261029.md`. The S9 settings
below describe the original integration recipe, which remains selectable.

The implementation ports the reviewed OpenWAM-accel S9 code from
`perf/train-accel-3src`, commit `b3262361c78cb24a42ad5760e68dc70b83bd5a53`, onto the
six-source TouchWAM training implementation. Dataset readers, publication
contracts, full OpenWAM Alpha initialization, FTP observation encoder weights,
modality-aware AdamW, gradient accumulation and resumable checkpoints are kept.

## Launch

The existing six-source launcher now defaults to
`train_touchwam_six_source_20261029_s9`. Its default mode remains `check`.
On dev-cpu / the mounted training worker, use the established OpenWAM environment:

```bash
cd /mnt/pfs/v89atp/workspace/OpenWAM-touchwam-training
export PYTHON_BIN=/mnt/pfs/v89atp/workspace/envs/openwam/bin/python
bash scripts/train_touchwam_six_source.sh check
# On allocated GPU workers, with the existing distributed launch environment:
bash scripts/train_touchwam_six_source.sh train
```

The launcher selects the separate S9 Alpha audit at
`setup/touchwam_s9_integration_20261029/alpha_bitwise_audit.json`; the original
recipe retains its original audit. Enabling split attention changes the model
configuration fingerprint, so the old audit cannot be silently reused. Data
and model mounts must match the original six-source recipe. This change does not
submit a job or alter the requested training allocation, sampling mixture,
batch size, learning rate or training horizon.

Reference implementation / fallback:

```bash
TOUCHWAM_CONFIG=train_touchwam_six_source_20261029 \
  bash scripts/train_touchwam_six_source.sh check
```

For a matched short speed run, use `training.stop_after_steps=100` (at least
several steps beyond compile warmup), rather than changing `max_steps`.
`stop_after_steps` preserves the full LR horizon and finishes the active gradient
accumulation window. It still follows the configured checkpoint policy. Resume
with the existing `resume` launcher mode and remove the short-run stop override
when continuing a full run.

## Enabled options

- Text padding to the longest prompt; within-batch prompt deduplication.
- Worker-stacked uint8 video clips, pinned / non-blocking uploads.
- VAE cuDNN autotuning, channels_last_3d and compiled normalization fusion;
  equivalent native spatial padding for causal Conv3D.
- Per-frame time modulation and compiled Wan block regions. RoPE stays fp64.
- Full-layer activation checkpointing on backbone layers 0–19; all 30 layers
  still train. Tactile bridge checkpointing is preserved. Set
  `training.gradient_checkpointing_layers=all` if more activation memory savings
  are needed; adjust batch only after measuring the actual modality layouts.
- Exact attention-mask decomposition for the video/action driver and TouchWAM's
  no-action tactile path. Pure video keeps its existing native unmasked graph;
  no causal mask is newly imposed. Unsupported masks retain masked SDPA.
- DeepSpeed gradient communication overlap and deferred ZeRO-1/2 parameter
  all-gather. Parameter values are awaited before any trainable tactile/video/
  action encoding, and before checkpoint saves. Unknown preprocessing paths or
  trainable preprocessing modules wait earlier. The patch is restored on exit.
- Buffered CSV and JSONL metrics, flushed at checkpoint / exit. A fixed CSV
  schema supports alternating no-touch, intensity and RGB batches. A hard crash
  may lose the last 49 buffered metric rows, not a saved checkpoint.
- Stage timing every 50 steps. MFU defaults off: the upstream first-batch FLOP
  estimate is not representative of the changing six-source modality graphs.

## TouchWAM-specific adaptations

`touchwam/architecture.py` owns its backbone/bridge loop, so copying the upstream
YAML alone would not activate split attention or checkpoint layer selection.
The loop now configures both explicitly, including the V/VT path without action
tokens. The VT mask preserves all clean prefix frames, not only frame zero.
The existing no-region V/VA bypass remains intact.

The trainer retains global modality/codec/observation-shape alignment and active
optimizer-group tracking. Deferred synchronization overlaps only the known
frozen input path, and is completed before the trainable heterogeneous tactile
frontends execute. ZeRO stages other than 1/2 are rejected for this option.
Channels-last VAE weights are made contiguous when writing safetensors while
preserving TouchWAM checkpoint metadata.

## Verification

Local environment: PyTorch 2.7.1, CUDA 12.8, RTX 4090. The CPU regression run
used PyTorch CPU convolution fallback because this host's oneDNN lacks BF16
convolution backward; no production backend setting was changed.

- 393 regression tests passed, including all existing TouchWAM tests, loss and
  gradient comparisons for V/VA/VT/VAT and RGB/intensity, clean-prefix isolation,
  real optimizer/scheduler checkpoint resume, and two-process Gloo tests.
- 41 upstream fusion/compute tests passed, covering VAE, convolution padding,
  Wan block forward/backward and compile-after-FLOP-counting behavior.
- 2 actual CUDA BF16 compiled TouchWAM tests passed, with VT and VAT RGB inputs,
  gradient comparisons and real optimizer updates.
- A real single-GPU DeepSpeed ZeRO-2 check passed six updates switching V, VA,
  VT and VAT with intensity/RGB codecs, compiled blocks and gradient overlap.
  Active groups changed and inactive weights/Adam state stayed unchanged.
  The deferred gather patch was installed; actual cross-rank gathering is
  separately covered by the two-process Gloo test.
- Short-run LR matching, update-boundary stopping, buffered logging across
  codecs, deferred wait ordering, and patch cleanup on failure are covered.

The upstream 64-A800 three-source experiment measured 9.98 → 5.78 seconds/step.
That is not a six-source tactile benchmark. This port's local tests use small
real Wan/ActionDiT/TouchWAM models; full-size multi-GPU throughput and memory must
be measured with this accelerated recipe. The previous eight-GPU six-source
acceptance run used the pre-acceleration code and does not validate S9.
